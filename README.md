# Vektor Auto

Портфельный продукт для универсального автосервиса: премиальный адаптивный лендинг, настоящая форма заявки и готовая связка с n8n, Telegram, Google Calendar и отдельной админ-группой.

> Это демонстрационный проект. Не используйте реальные персональные данные при проверке.

## Что внутри

- `index.html`, `styles.css`, `app.js` — сайт без клиентского фреймворка;
- `server.mjs` и `lib/lead.mjs` — локальный сервер и защищённый шлюз формы;
- `workflow/Vektor-Auto-V2.3-Website-Demo.json` — актуальный workflow для импорта;
- `workflow/Vektor-Auto-V2.2-Portfolio-Demo.json` — неизменённая исходная копия;
- `docs/DEMO-SCRIPT.md` — сценарий презентации;
- `api/` и `vercel.json` — готовый тонкий слой для будущей публикации на Vercel.

## Быстрый локальный запуск

Нужен Node.js 20 или новее. Зависимости устанавливать не требуется.

1. Скопируйте `.env.example` в `.env`.
2. Заполните три значения в `.env` по инструкции ниже.
3. Запустите:

   ```powershell
   npm start
   ```

4. Откройте `http://localhost:3000`.

Порт можно изменить через `PORT`. Автоматические проверки запускаются командой `npm test`.

## Подключение n8n

1. Импортируйте `workflow/Vektor-Auto-V2.3-Website-Demo.json`.
2. В Data Table «Заявки автосервиса» добавьте строковую колонку `request_id`.
3. В n8n создайте credential типа **Header Auth**:
   - имя заголовка: `x-vektor-token`;
   - значение: длинная случайная строка.
4. Назначьте credential узлу **Website Gateway**.
5. Скопируйте production URL этого Webhook в `N8N_WEBHOOK_URL`.
6. Запишите то же значение заголовка в `N8N_WEBHOOK_TOKEN`.
7. В `TELEGRAM_BOT_USERNAME` укажите имя бота без ссылки, например `VektorAutoDemoBot`.
8. Проверьте credentials Telegram, Google Calendar, OpenRouter и Data Table, затем активируйте workflow.

Пример `.env`:

```dotenv
N8N_WEBHOOK_URL=https://n8n.example.com/webhook/vektor-auto-lead
N8N_WEBHOOK_TOKEN=replace-with-a-long-random-value
TELEGRAM_BOT_USERNAME=VektorAutoDemoBot
PORT=3000
```

Файл `.env` игнорируется Git. URL и токен никогда не передаются в браузер.

## Как проходит заявка

```text
Сайт → серверная проверка → n8n → Data Table → Calendar → админ-группа
  ↘ Telegram-ссылка с request_id → бот Анна → подтверждение клиенту
```

После отправки сайт создаёт непрозрачный `request_id`. Клиент открывает Telegram по персональной ссылке, бот связывает чат с записью, и дальнейшие решения администратора приходят клиенту туда. Исходный диалог с Анной и встроенная форма n8n продолжают работать.

## Будущий деплой на Vercel

Проект уже содержит serverless-функции для `/api/lead` и `/telegram`.

1. Импортируйте репозиторий в Vercel с пресетом **Other**.
2. Оставьте build command пустой, а в Output Directory укажите `.`.
3. Добавьте `N8N_WEBHOOK_URL`, `N8N_WEBHOOK_TOKEN` и `TELEGRAM_BOT_USERNAME` в Environment Variables.
4. Выполните preview-проверку, затем включите production deployment.

Публичный деплой в рамках этой версии намеренно не выполнялся.

## Безопасность

- повторная валидация всех полей на сервере;
- лимит тела запроса 16 КБ;
- honeypot против простых ботов;
- не более пяти попыток с одного IP за десять минут;
- блокировка одинаковой заявки на две минуты;
- таймаут запроса к n8n;
- секретный заголовок только на сервере;
- содержимое заявки не пишется в журнал.

Перед реальным использованием замените демонстрационные тексты, добавьте юридические документы и подключите постоянное распределённое ограничение частоты на уровне хостинга.
