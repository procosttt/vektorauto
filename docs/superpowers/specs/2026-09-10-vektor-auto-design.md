# Vektor Auto — дизайн продукта

## Цель

Создать портфельный одностраничный сайт универсального мультибрендового автосервиса, который выглядит как готовый коммерческий продукт и демонстрирует реальную связку сайта с n8n, Telegram, Google Calendar и админ-группой.

## Позиционирование

Vektor Auto — современный автосервис для диагностики, технического обслуживания, автоэлектрики, шиномонтажа и кузовного ремонта. Основное обещание: клиент оставляет одну понятную заявку, администратор проверяет время и подтверждает запись без телефонной очереди.

Проект демонстрационный. На сайте рядом с формой запрещено вводить реальные персональные данные, а в футере явно указан портфельный статус. Выдуманные отзывы, рейтинги, адреса и статистика не используются.

## Структура страницы

1. Компактная шапка с логотипом, навигацией, CTA формы и ссылкой на Telegram.
2. Первый экран с крупным оффером, автомобилем, двумя CTA и доказательством автоматизированного процесса.
3. Четыре направления работ: ТО и диагностика, ходовая и тормоза, автоэлектрика, кузов и шины.
4. Три шага записи: заявка, проверка времени, подтверждение.
5. Блок преимуществ без недоказуемых цифр: согласование до работ, прозрачный статус, напоминания, человек принимает финальное решение.
6. Контрастный блок заявки с настоящей формой и альтернативой через Telegram.
7. Короткий блок контакта и демонстрационный футер.

## Визуальное направление

Светлый кремовый фон, почти чёрная типографика и красный акцент. Крупный гротеск, техническая сетка, метки и паттерн протектора создают индустриальный характер. Главный объект — оригинальный фотореалистичный графитовый автомобиль в ракурсе три четверти с красным световым акцентом. Дизайн использует язык референса, но не повторяет его композицию, логотип, тексты или изображения.

На мобильном первый экран перестраивается в одну колонку, автомобиль не перекрывает текст, кнопки имеют достаточную площадь касания, а форма использует нативные поля даты и времени.

## Техническая архитектура

Сайт реализуется на HTML, CSS и браузерном JavaScript без клиентского фреймворка. Локальный Node.js-сервер раздаёт статику, загружает `.env` и предоставляет:

- `POST /api/lead` для проверки и передачи заявки в n8n;
- `GET /telegram` для безопасного перехода к боту;
- статические файлы сайта.

Сервер использует только встроенные модули Node.js и глобальный `fetch`. Та же функция обработки заявки совместима с будущей serverless-функцией Vercel.

## Поток данных

1. Браузер проверяет обязательные поля, согласие с демо-режимом и пустой honeypot.
2. Сервер повторно проверяет данные, ограничивает частоту по IP и блокирует одинаковую заявку на две минуты.
3. Сервер создаёт `request_id`, отправляет заявку в production Webhook n8n и добавляет секретный заголовок из `.env`.
4. n8n нормализует заявку, классифицирует услугу, сохраняет лид, проверяет Calendar и отправляет карточку администратору.
5. Сайт показывает успешный статус и ссылку `t.me/<bot>?start=site_<request_id>`.
6. Telegram-бот связывает чат с лидом по `request_id`. После решения администратора существующая ветка отправляет подтверждение клиенту.

## Безопасность и ошибки

- URL и токен n8n существуют только в `.env` на сервере.
- Размер тела запроса ограничен 16 КБ.
- Поля обрезаются по максимальной длине; телефон нормализуется и проверяется.
- Honeypot, IP rate limit и краткая дедупликация снижают спам и повторные клики.
- В интерфейсе нет технических деталей отказа n8n; пользователю предлагается Telegram.
- Кнопка отправки блокируется на время запроса и после успеха.
- Сервер не пишет содержимое заявки в журнал.

## Workflow

В проект кладётся копия V2.2. В ней добавляется защищённый Webhook сайта, поддержка `request_id` и ветка связывания Telegram-чата с заявкой. Исходная n8n Form Trigger и Telegram-диалог сохраняются.

Перед запуском пользователь создаёт колонку `request_id` в Data Table и назначает Webhook узлу Header Auth credential с заголовком `x-vektor-token`.

## Проверка

Одна проверка Node.js покрывает валидацию, honeypot, дедупликацию, отсутствие конфигурации и успешную передачу на подставной n8n endpoint. Дополнительно проверяются JSON workflow, desktop-страница и мобильная ширина 390 px.

## Вне объёма

Личный кабинет, оплата, отдельная CRM, каталог запчастей, блог, CMS и публичный деплой не создаются.
